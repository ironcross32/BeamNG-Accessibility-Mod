# Lua: Assorted GE Extensions

- **`lua/vehicle/protocols/796F6C6F313035.lua`** — Extended UDP telemetry for the active vehicle. Wheel telemetry recognizes the semantic positions `F`, `FL`, `FR`, `R`, `RL`, and `RR`; the packet appends centred-wheel pressure/temperature values plus a telemetry-presence mask so Python can omit positions the current vehicle does not have. That mask also distinguishes a real clutch temperature from the zero placeholder sent by vehicles without clutch thermals. Friction and centrifugal clutches expose Celsius as `device.clutchTemperature`; if several thermal clutch devices exist, Lua sends the hottest. The fields are appended rather than inserted, and Python retains decoders for every earlier packet length. The newest tail is the raw fastest-driven and slowest wheel speed for slip detection (see `lua-telemetry-protocol.md`). Brake readouts use BeamNG's live `brakeSurfaceTemperature`, not the unrelated electrics dump or the slower brake-core value. Vehicle-Lua protocol edits require a vehicle reload or respawn; Ctrl+L reloads the game-engine VM only.
- **`lua/ge/extensions/accessibilityInput.lua`** and **`lua/ge/extensions/core/input/actions/beamtel_accessibility.json`** — Add an `Accessibility` controls category and six initially unbound Normal actions for up, down, repeat, next menu, previous menu, and activate. The extension adds one key to BeamNG's live `core_input_categories` table instead of replacing the game's category file, allowlists the six semantic command names, and forwards them as `accessibility_action` JSON through `bnvdaBridge`. It is manual like the bridge so ordinary Lua reloads keep the controller path alive. Screen state, catalogs, formatting, and command execution stay in Python.
- **`lua/ge/extensions/beamtelAI.lua`** — AI mode control (chase, follow, flee, stop). Receives commands on port 4449.
- **`lua/ge/extensions/obstacleDetector.lua`** — 13-ray trajectory-aware static-obstacle selection plus unchanged terrain drop-off/hill sampling. Rays begin at resolved `vehicleGeometry` extents, use forward/reverse and steering state from Python, require two-height confirmation, and emit one hysteretic surface-gap hazard. Port 4452→4453. See [obstacle-warning.md](obstacle-warning.md).
- **`lua/ge/extensions/roadDetector.lua`** — Navigation-graph road acquisition, lane correction, and junction guidance on ports 4462→4463. Its ordinary `R2` packet stays compact; the recorder's `DIAG_ON` command temporarily adds the selected edge, lateral/predicted/target geometry, heading and correction errors, all three settled predicates, and the clear-tick counter. The independent `CAPTURE_ON`/`CAPTURE_OFF` consumer keeps 20 Hz packets and 10 Hz wheel-contact details flowing during the hill-climb challenge without enabling road-guidance speech or disturbing an MCP diagnostic session. See [road-guidance-diagnostics.md](road-guidance-diagnostics.md). It also selects the stop bar carried in `R2.proximity` (`stopBarAt`), and routes the driving assistant over gated, private and rough roads that manual guidance leaves out; see [junction-proximity-validation.md](junction-proximity-validation.md).
  - **Surface changes, always on.** Every 0.2 s, whether or not road detection or the assistant is on, `onUpdate` queues `SURFACE_COMMAND` into the player vehicle. It reports the ground model most wheels touch (`contactMaterialID1`; ID2 is the tyre's own `RUBBER`). A tie or no contact keeps the current reading. `onSurface` reduces the name to a family word (`DIRT_DUSTY` → Dirt, `ASPHALT_WET` → Asphalt, unknown → silent), takes the first reading as the start rather than a change, and needs the new word to hold for `SURFACE_SETTLE_M` (8 m) of travel. It then sends `SURFACE|<Word>|<0/1>` on 4462, with 1 when a mapped road is within its radius plus 1 m, and Python says "Dirt road" or "Grass". Older receivers ignore the unknown packet. `surfaceState()` shows the live reading.
  - **No street names exist to announce.** A check of seven stock levels, Johnson Valley's live scene included, found no road name anywhere: DecalRoads carry no `annotation` or `internalName`, and the only non-numeric names are editor labels (`d_logging_b`, `highway_one_line_1`, `TRAFFIC_SIGNS`). Node IDs like `DR435_3` are the navgraph's per-road index. That is why the surface is what gets announced.
- **`lua/ge/extensions/hillClimbChallenge.lua`** — Filters the native Proving Grounds time-trial mission and relays start, checkpoint, completion, aggregation, abort, and mission-stop events through `bnvdaBridge`. BeamNG remains authoritative for timing, penalties, recoveries, and personal-best progress; the extension only supplies lifecycle boundaries and split metadata to Python.

- **`lua/ge/extensions/nodeGrabberAccessible.lua`** — Accessible node grabber. Ray-sphere node detection under mouse cursor, cross-VM node metadata caching, SNAP cursor warp. Port 4454→4455.
  - `UNPIN` (Ctrl+Space while the grabber is on) calls `be.nodeGrabber:clearVehicleFixedNodes(id)` for **every** vehicle — the call `lua/vehicle/recovery.lua` uses — and replies `UNPINNED:<n>` or `UNPIN_FAILED`. The game exposes no way to list pinned nodes, so it is all-or-nothing, and Python speaks only on the reply rather than assuming the send worked. The Python hook swallows Space only while Ctrl is down, so the handbrake is untouched, and ignores auto-repeat until Space is released.
  - **Controller node grabber (0.39+).** The game's `core_nodegrabberGamepad` (bound to `nodegrabberPadMode`) switches to the relative camera and puts the C++ grabber into controller mode, which aims at the screen centre. It shows no message on toggle and drops out by itself on a camera change, CEF hide, vehicle reset or Ctrl (mouse mode). So `onUpdate` polls `state.active` **every frame, whether or not the accessible grabber is on**, and sends `PADMODE:1/0` on change. Python says "Controller node grabber on/off". It reads the module with `rawget(_G, ...)`, because `extensions.lua`'s `__index` *loads* a module on first access.
  - While the accessible grabber is on and pad mode is active, the scan needs no Ctrl and uses `findCenterNode`: the node nearest the camera's forward ray within a cone of tangent `PAD_PICK_TAN`. That is wider than the mouse path's hit sphere, which a crosshair aimed by ear would almost never land in. `be.nodeGrabber` has no getter for the node it targets, so this is our best estimate of the game's pick, not a readout of it. Hover is frozen while `state.grabbing` is true. `GRAB:1/0` comes from `state.grabbing` (mouse grabs too). `ON` replies with a quiet `PADSYNC:x` for a Python that started after the last change.
  - Pins: `nodegrabberAction` (middle mouse, or the pad's action button) calls `core_nodegrabberGamepad.fixCurrentNode` in both modes, and the action map resolves that field at press time. The extension wraps it to send `PINNED`, and restores it in `onExtensionUnloaded` so a reload does not wrap the wrapper twice. This replaced Python's middle-click guess.
- **`lua/ge/extensions/clickspotAccessible.lua`** — Accessible clickspot detection. Enumerates vehicle interior trigger volumes, detects hover via `be:triggerRaycastClosest()`, and executes trigger actions directly. Port 4456→4457. `TRIGGER_LIST_PENDING` invalidates Python's published rows as soon as activation, recache, or a player-vehicle switch begins; `TRIGGER_LIST_OFF` synchronizes detector shutdown and world resets. The existing count followed by indexed rows lets Python stage and atomically publish a complete, cache-ordered controller list.
- **`lua/ge/extensions/uiToggle.lua`** — Hides/shows the game UI on command (`ui_visibility.set`/`toggle`, the same thing ALT+U toggles). Used by the AI Describer to remove HUD elements before a screenshot. Port 4464.
- **`lua/ge/extensions/consoleAccessible.lua`** — Screen-reader-accessible equivalent of the stock ImGui developer console (the backtick `` ` `` console, which exposes no accessibility tree). Re-implements its execution model: runs commands in the GE Lua (via `executeLuaSandboxed` for captured return + print output), GE TorqueScript, CEF/UI JS, and per-vehicle Lua contexts; enumerates those contexts on demand; and can stream the global engine log (`Engine.getFrameLog()`). Surfaced through native wx controls on beamtel.py's Main tab. Port 4465→4466.
- **`lua/ge/extensions/vehicleBindings.lua`** — Vehicle-specific control bindings, the data behind the stock "Special Vehicle Keys" app (`ui/modules/apps/Keys`), which is pure Vue and has no accessibility tree. Port 4467→4468; surfaced as a virtual browser on F9 then B. Rebuilt silently on every vehicle load — **it must never speak**, or it would talk over the spawn.
  - The list is a join the game does not expose as one call: iterate `core_input_bindings.bindings` → `device.contents.bindings`, look up `core_input_actions.getActiveActions()[binding.action]`, keep `cat == "vehicle_specific"`, drop `binding.unused` and `core_input_actionFilter.isActionBlocked()`. This mirrors the unexported `getVehicleSpecificActions()` in the game's `lua/ge/extensions/ui/bindingsLegend.lua`, except that function discards `binding.control` and we keep it. **Filtering on `cat` is also the part-config capability check** — `core/input/actions.lua` resolves usability against `vdata.actionsEnabled` and demotes anything the current config cannot do to `vehicle_specific_unusable`, so a Pickup without a locker correctly shows no Toggle Rear Diff. Driving the list from `bindings` rather than from the action table is also what makes it bound-only.
  - Same `vdata`-not-ready trap as clickspots: `onVehicleSwitched` fires before `vdata.inputActions` exists, which is what feeds `getActiveActions()`. Hence the same retry harness (0.5 s × 10) plus a `be:getPlayerVehicleID(0)` poll in `onUpdate` as a backstop. An **empty** result is treated as "still loading" until the retry budget runs out, because that is indistinguishable from "no special controls" at the first attempt.
  - Key names are prettified **in Lua**, which the game does not do anywhere: `CONTROL_LABELS`/`controlLabel()` live only in `ui/ui-vue/src/services/controls.js` and compress for display with glyphs (`PG↑`, `L⇧`, `NP0`) that a screen reader cannot read. `KEY_LABELS` is that mapping expanded for speech instead, modifiers joined with `" plus "`, keyboard given no device prefix (`L`, not `keyboard L`) since it is the common case. Devices are read keyboard-first — the reverse of the stock `DEVICE_ORDER` — so a listener can stop after the key.
  - Enter fires the action through `core_input_actions.triggerDownUp`, i.e. the same ActionMap path a real key press takes, so onDown/onUp pairing stays correct. Unlike the clickspot browser this needs no delayed press/release thread on the Python side.
