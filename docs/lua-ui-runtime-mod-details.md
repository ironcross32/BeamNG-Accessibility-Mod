# Lua/JS: UI Runtime: Mod details page text

Part of `ui/ui-vue/mods/bnvda/bnvdaRuntime.js`. The overview, the poll/event model and the shared text helpers are in `lua-ui-runtime.md`.

The page text read on request for the mod repository and automation details pages.

- **The mod repository details page is READ ON REQUEST, and it is the first thing in this file that is not driven by focus.** The repository is still AngularJS in 0.39 (`ui/modules/repository/`, routed from `entrypoints/main/main.js:592`), and it splits over two views: `repository-details.html` is a single `<div ng-bind-html="repoDetailCtrl.modData.message">` holding the BBCode-rendered description, and `info.html` is the spec table plus the subscribe buttons. **Only the buttons are nav items.** The description and the whole `table.repodetailtable` carry no `bng-nav-item`, no tabindex and nothing focusable at all, so a controller sweeps straight past both onto Subscribe and the focus path never fires once — every word of what a mod actually *is* was unreachable rather than merely terse. `menu.mods.automationDetails` renders the identical `ng-bind-html` shape, so one selector covers both. Python asks with a `page_text` message and renders the reply in the virtual browser it already has; there is no watcher and nothing is read automatically, which is the correction the deleted `bnvda_hook/app.js` DOM-scraping poller earns.
  - **The description is read from the RENDERED DOM, never from `modData.message`.** That field is not a string: `repository.js:296` replaces it with an Angular `$sce.trustAsHtml` wrapper object, and the DOM already holds the parsed BBCode the sighted player is looking at. Reading the scope would also put us in a listener-ordering race with the stock controller, which is doing that replacement on the same `ModReceived` broadcast. `mod_details_sim.js` scenario 7 greps for the field name with **comment lines stripped**, because the prose explaining this rule has to write it — the trap `vehicle_geometry_sim.lua` scenario 12 already fell into.
  - **`cleanText` is the wrong tool for body text and must never touch it.** It truncates at `MAX_LEN` (160) with an ellipsis, which on a paragraph reads as though the mod author stopped writing mid-sentence — a confident wrong answer with nothing to distinguish it from a real one. `blockText` is the same glyph strip and whitespace collapse with **no cap**, and `pushBlock` splits anything over `MOD_BLOCK_MAX` on **sentence ends** rather than at a character count, so nothing is cut mid-word and nothing is lost. Scenario 2 asserts the round trip is lossless and asserts `cleanText` would have truncated the same fixture.
  - **Structure is preserved by walking BLOCK elements, not by taking one `innerText`.** A whole-body `innerText` is one run-on line with no boundary a listener can arrow to — the paragraphs run together (`truck.Requires`). `collectBlocks` emits a line per block, bullets `li`, skips `img`/`script`/`style`, and keeps `a` text inline. **`BR` is in `MOD_BLOCK_TAGS` deliberately**: it emits nothing itself, but its presence sends its parent down the mixed path, so the line breaks the author typed survive. `MOD_MAX_LINES` caps a runaway description; a runaway list is no more navigable than a runaway paragraph.
  - **The rating row is COUNTED, not read.** `jk-rating-stars` renders a strip of Material-icon divs whose text is the word `star` five times over — which says nothing whatever about how many are lit, i.e. about the entire content of the row. `modRatingText` counts `.star-button` against `.star-button.star-on` and answers `4 out of 5 stars`. Keyed on that structure rather than on the row label, which is localized. The rest of the table needs no `findTranslateFunc()` pass at all: Angular has already translated the labels and already applied the game's own `bytes` and `date` filters to the values, so the readout cannot disagree with the screen.
  - **The screen latch is pushed on entering AND on leaving, and again on every transport pong.** The latch exists only so the controller Functions menu can hide the entry everywhere else; the readout itself always asks the runtime, which answers `notdetails` if the screen has since gone. Pushing on both edges is what stops the latch sticking on a page the driver walked away from, and the pong re-push is what covers **beamtel restarting while the UI stays up** — no route change would follow to refill it, which is the same argument the `loading_state` re-send in that branch already makes.
  - **`F9` `SPACE` gates on the latch BEFORE the round trip, and speaks only real failures.** That key is the terrain scan and is pressed while *driving*, so the ordinary case has to cost nothing — and `notdetails`, the answer on every other screen in the game, must fall through in silence or the scan is replaced by a complaint on a key that has always scanned. A **timeout** is a statement about the UI half being missing or out of date, not about the mod, and is silent for the same reason `vehicleInfo.lua`'s is. The controller entry is the opposite call: it only appears while the latch is on, so every failure there *is* news and is spoken.
  - `diagnostic/mod_details_sim.js` (`node diagnostic/mod_details_sim.js`) replays all of it against a fake DOM built to the shape the two templates emit, lifting the functions out of the source by name for the reason `binding_readout_sim.js` gives, and asserting the naive answer in every scenario. The transport wiring, the route subscription and the pong re-push are grepped, because no fake DOM reaches them.
