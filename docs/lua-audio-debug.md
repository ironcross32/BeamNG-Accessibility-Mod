# Lua: `audioDebugAccessible.lua` and `beamtelAudioDebug.lua`

- **`lua/ge/extensions/audioDebugAccessible.lua`** (GE, ports 4483→4484) and **`lua/vehicle/extensions/beamtelAudioDebug.lua`** (vehicle VM, loaded on demand) — the World Editor's **Window > Audio** tools as a virtual browser (`F9` `J`). Those windows are ImGui, so they have no accessibility tree; this reads and writes what is behind them. Python side: `audio_debug.py` (pure parsing, wording, stepping) and the `_aud_*` glue in `beamtel.py`. Sim: `python diagnostic/audio_debug_row_sim.py`.
  - **What is covered, and what is not.** *Engine Audio Debug* (`editor/engineAudioDebug.lua`): every engine sound's live parameters. *SFX Previewer* (`editor/audioEventsList.lua`): the sound event library, played on Enter. *Suspension Audio Debug* is deliberately left out: it is read-only graphs of per-corner beam-sound impulse, pitch and volume, with nothing to act on.
  - **None of it needs the editor.** `sounds.getEngineSoundData()`, `Sim.getSFXTrackSet()` and `Engine.Audio.playOnce('AudioGui', ...)` all work with the editor closed (measured in 0.39). The stock windows only *draw* inside the editor.
  - **The parameters live in the vehicle VM**, in each powertrain device's `soundConfiguration[ref].params` (`ref` is `engine`, `exhaust`, or `motor` for an electric motor), and are written with `device:setEngineSoundParameterList(soundID, params, ref)`, which forwards to `core_sounds` in GE. GE only ever sends one-line calls (`extensions.load("beamtelAudioDebug") ... .set("id","key",value)`), the `beamtelAssistant` pattern, so no cross-VM chunk carries a format template. Every call, including a refused one, is answered by `onVehicleData(payload)`, which is the one place a reply becomes rows; a missing reply becomes "The vehicle did not answer" after 1 s, inside Python's own 1.5 s "No response from the game".
  - **Three bugs in the stock window that this does not copy:**
    - It *displays* `main_gain`/`muffled` — aggregates that include the exhaust part's and rev limiter's offsets — and *writes them back* as `base_gain`/`base_muffled` with every offset zeroed. Touching any control wipes the gain change the fitted exhaust applied. Here the base is read, and the FULL current table is sent with one field replaced.
    - `electricMotor.setEngineSoundParameterList` does not derive `main_gain`/`muffled` from the base values the way `combustionEngine`'s does, so the stock main gain and muffling controls do nothing on an EV. Here an EV (`device.type == "electricMotor"`) is written `main_gain`/`muffled` directly.
    - `electricMotor` takes its fundamental frequency from `device.fundamentalFrequencyRPMCoef`, not from the table, so the cylinder control is not offered on an EV at all — it would be a control that answers and changes nothing.
  - **`getEngineSoundData` is not used for the list**: it walks the configuration with `pairs()`, so its order is not stable between calls, and its table is 0-based (`ipairs` skips the first sound). The vehicle module builds its own list, sorted by engine then reference.
  - **Frequencies are stepped on FMOD's 0–1000 scale and spoken in Hz.** The table is a piecewise-linear map over 20/40/80/160/330/660/1300/2700/5400/11000/22000 Hz, 100 units a segment, so 10 units is roughly a tenth of an octave everywhere. The stock window's fixed 100 Hz step is far too coarse at 50 Hz and pointlessly fine at 10 kHz. The GE copy of the table is checked against the stock window's by the sim. Steps are not snapped to the grid, so a vehicle's own value (382.35) stays reachable by stepping back.
  - **Restore puts back only the editable fields.** The rest of the parameter table is live — the rev limiter and exhaust part rewrite `gainOffset`/`mufflingOffset*` while the engine runs — so restoring the whole snapshot would pin them. Originals are captured per sound on first sight; a vehicle reload rebuilds the VM and so empties them, which is right, because it also rebuilds the sounds from jbeam.
  - **"Copy as jbeam" uses jbeam's own key names**, unlike the stock export: the engine's muffling key is `intakeMuffling` (the stock window exports `muffling`, which nothing reads); the exhaust's muffling is derived from the fitted exhaust part and so has no key; an exhaust's `base_gain` is jbeam `mainGain` *plus* the part's gain change, so that share (`exhaustPartGain`) is subtracted; an EV's shelves are `lowCutFreq`/`highCutFreq`.
    - **The clipboard is written through `ui_imgui.SetClipboardText`.** The global `setClipboard` the stock window uses returned `false` and left the clipboard untouched when measured with the game in the background — which is where it is when the user alt-tabs to paste.
  - **Sound library.** The tree is rebuilt on every root listing and addressed by 0-based child indices (`SFX_LIST:12>3`), not names, because names go through `sanitize` and would not round-trip. An object's name is used when it is an `event:>` path, otherwise its sound filename — and that filename is often an `event:>` path too (measured: a few dozen), so the split (`>` or `/`) is chosen by the resolved name's form; choosing by accessor dumped them at the root as single long names. A name seen twice is listed once. Sounds play at the **camera**, the listener, rather than at the vehicle as the stock previewer does, so they arrive centred and unattenuated. A looping event plays until stopped, which is why every folder leads with a "Stop sound" row and leaving the library stops playback.
  - **Wire format.** Named fields as `environmentAccessible`: `AUD_BEGIN:<n>;soundCount=<c>`, `AUD:<i>;key=..;kind=select|number|action|info;...`, `AUD_END`; `AUD_SFX_BEGIN:<n>;path=;total=`, `AUD_SFX:<i>;kind=dir|event;name=;count=|id=`, `AUD_SFX_END`; `AUD_ERROR:<reason>` and `AUD_DONE:<message>`, both spoken. Commands: `REQUEST`, `SELECT:<i>`, `SET:<key>=<value>`, `RESTORE`, `COPY`, `SFX_LIST:<path>`, `SFX_PLAY:<id>`, `SFX_STOP`. An error is followed by a fresh row set, so Python drops the "speak the current line" it was waiting for — reading it would cut the reason off.
  - **Not in the controller Functions menu**, for the environment browser's reason: the pad has no left/right action, so the engine controls could not be adjusted from it.
