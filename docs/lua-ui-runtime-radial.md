# Lua/JS: UI Runtime: Radial menu speech

Part of `ui/ui-vue/mods/bnvda/bnvdaRuntime.js`. The overview, the poll/event model and the shared text helpers are in `lua-ui-runtime.md`.

The radial (quick access) menu: the centre label, the stick used as a pointer, and the submenu and category path.

- **The centre is read from `RadialSVG`'s callbacks, not the DOM** (`installRadialCenterHook`, `radialWrapEvents`). Up to 0.39 the centre was painted on a canvas by `radialCenterCanvas.js` and we wrapped its `setState`. **0.40 deleted that file**: the centre is now a Vue-rendered `.radial-center` div fed from a ref private to `Radial.vue`'s setup. `index.js`'s import 404'd, the hook never installed, and the only symptom was silence with the interface clicks still playing (the clicks are `RadialSVG`'s own `focus` event). `index.js` now imports `@/modules/radial/radialsvg`, and the runtime wraps `RadialSVG.prototype.update`:
  - Each wedge's `focus()`/`blur()` calls the `centerFocus`/`centerBlur` callbacks `Radial.vue` gives the instance, with the item. The wedges look them up on the instance's `events` object at call time, so the first `update()` -- which runs before any wedge exists -- wraps them there. Only the newest instance is kept wrapped; the cleanup puts back the prototype and the callbacks.
  - `requestData()` also sets the centre **directly**, default then the item still marked focused, around `update()`; the wrapper reports that pair itself, so the rebuild logic below is unchanged.
  - The label is built from the item the way `getCenterLabel` does (`$ctx_t(desc, false)`: context left untranslated, the opposite of `$ctx_t`'s default), and the price from `item.price.money.amount`. Reading `.radial-center-label` instead would see only the end of each pair, because Vue renders it asynchronously.
  - A `reloadUI()` that lands straight back on `#/radial` mounts the menu before the runtime reinstalls, so that one instance is silent until its next `update()` (switching category, or reopening). Only matters when testing.
- **The radial menu's centre readout does not speak the item's binding.** It would follow every wedge, so sweeping the menu reads a button name after every single item. (In 0.39 it was also wrong: `getHotkey` named the raw control of whichever pad came first in the bindings list.) The item name is what the menu is navigated by; the shortcut is not worth the interruption.
- **Radial item names bypass `scheduleSpeak` and the nav burst entirely** (`radialSpeak`). The radial is a pointer, not a list: every wedge the stick crosses is a position the player chose. But the stick counts as a held direction in `trackNavigationInput`, so `navBurstCapture` took every wedge after the first for a key repeat and held it until release — a slow rotation spoke three wedges out of eight, the last one after the stick was let go — and its 400 ms same-text dedup swallowed a quick re-press of the item just released. Each wedge is now spoken the moment it is focused, interrupting the last, and any pending burst text is dropped rather than flushed later.
  - **Decided once per synchronous pair, in a microtask, never on a timer.** `Radial.vue` changes the centre in pairs: `pointToItem` blurs the old wedge (back to the "Select an option" default) and focuses the new one, and `requestData()` resets to the default and re-focuses the item under the pointer. A pair that ends on the item already spoken is a rebuild and stays quiet; a default that survives the pair is the dead zone, which clears the dedup so returning to the same item speaks again. Vue's render flush was queued before ours, so the heading is already current when the microtask runs.
  - **A release crosses the neighbouring wedge, and must not name it.** The two axes (or two D-pad buttons) come up one at a time, so for a frame the pointer rests on the remaining axis alone: let go of "Exit vehicle" up-right and "Boost", straight up, was the last thing said. `radialNoteInput` tracks the pointer magnitude per device; a focus change made while it is *falling* is held `RADIAL_RELEASE_SETTLE_MS` (80 ms: two frames at 30 fps plus one stalled) and cancelled when the centre goes to the default. Pressing out and rotating never pay it. Measured through `lua_exec` injection the two axes arrive ~68 ms apart because each hop goes through GE, which is wider than a real stick — 60 ms let the stray name through in that test.
  - **The level is read as a path and only its new part is spoken** (`radialSegments`/`radialLevelAnnouncement`). Title, breadcrumb trail and category tab used to be joined as three strings, which said "Freeroam Actions, Freeroam Actions / Fun Stuff, Fun Stuff". Now entering says "Freeroam Actions, Fun Stuff", switching category says the category, going back up names where it landed, and the item under the pointer rides in the same utterance. It is read from the centre hook (the reset in `requestData()` means the data has arrived), not after two 200 ms poll ticks; the one reset that comes before data — at mount, heading still "No Actions Available" — has no wedges drawn and is left to the poll, which still covers a level with no items.
  - **A new `RadialSVG` instance is a newly opened menu.** `Radial.vue` makes one per mount, and the closed-menu poll runs once a second, so a quick close and reopen could otherwise keep the old path and stay silent.
  - `diagnostic/radial_sim.js` (`node diagnostic/radial_sim.js`) replays rotation, re-press, both release shapes, rebuilds, the path announcements and reopening against a model of `pointToItem`, lifting the functions out of the source by name. Scenario 12 drives the real `update()` hook against a model of 0.40's `RadialSVG`, and the wiring checks assert `index.js` still imports `radialsvg`.
- **Stick movement holds back the idle controller hint.** `radialSettle` calls `vueHintNoteActivity` on every centre change, because the hint's own activity check only sees DOM focus moves and there are none here. See `lua-ui-runtime-bindings.md`.
